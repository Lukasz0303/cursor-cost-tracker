## 2. Sztywne reguły produktowe

Obowiązują każdą funkcję. Plan funkcji nie może ich osłabiać.

| Reguła | Znaczenie |
|--------|-----------|
| **G5 — jeden blocking modal** | Tylko **critical alert** ostatniego zapytania (domyślnie 10M tokenów lub 5 $) może użyć `{ modal: true }`. Runaway i Daily Guard używają `showWarningMessage` **bez** `modal`, plus `warnColor` na pasku i banner na Statistics. |
| **Nie zatrzymamy Cursora** | Rozszerzenie nie pauzuje Composera / Agenta. Copy musi mówić, że ostrzeżenie nie zatrzymuje wydatków. |
| **Bez transkryptów** | Eventy usage nie mają conversation id (tylko timestamp, model, kind, tokeny, koszt). Bez treści czatu, skanu LLM workspace, auto-naprawy. Optimize zostaje promptami z metadanych. |
| **Bez 7. zakładki** | Last N / Statistics / Charts / Optimize / Support / Settings. Nowe UI w tych powierzchniach. |
| **Bez sekretów w webview** | Payload = sformatowane wiersze + statystyki. Nigdy cookie, access token, email poza tym, co PRD już pozwala. |
| **Show warnings** | Gdy `cursorCost.showSpikeWarning` jest off: brak `!` i zielonego/czerwonego na pasku i w tabeli. Tosty/bannery wg planu funkcji. |
| **Zapis ustawień** | Nowe liczby zapisują się na Apply / Enter / blur — nie w trakcie pisania (jak Show last / Critical alert). |
| **Zero-setup** | Nowe limity i detektory nie mogą zaskoczyć świeżej instalacji. Dzienny cap domyślnie **off** (`0`). Detektory tylko-ostrzegające mogą być **on**. |
| **Język** | Angielski w UI, opisach settings, commitach, `.ai` i testach. |
| **Wersjonowanie** | Każda funkcja to **MINOR** (`package.json`). PATCH tylko na poprawki algorytmu / copy po tym MINOR. Tagi git `vX.Y.Z`. |

## 3. Powierzchnie (wspólne)

```
UsageQuery[] ──► runaway detect ──► tost nie-modalny + ! na pasku + badge Last N + banner Statistics
            ├──► daily cap vs todayUsedUsd ──► mianownik chipa Today + tost + meter Statistics
            ├──► klaster sesji ──► karta efficiency score (Statistics)
            ├──► kubełek tokenów × model ──► karta advisor (Statistics)
            └──► stempel fingerprint (workspace + git) ──► paski by-project + filtr Last N + CSV
```

| Powierzchnia | Rola |
|--------------|------|
| Status bar | Chip Today używa **user** daily cap gdy ustawiony (1.3). Runaway koloruje chipy zapytań / `!` gdy warnings są on (1.2). |
| Tabela Last N | Zostaje TIME, MODEL, COST, TOKENS, INPUT / OUTPUT, KIND. Runaway = badge / flaga `runaway` (1.2). Atrybucja = **chipy filtrów**, nie 7. kolumna (1.6). |
| Statistics | Bannery + nowe karty (score, advisor, by-project). Glossary Current/Today, prognoza MTD, by-model / by-kind zostają. |
| Optimize | Opcjonalny extra **finding** z metadanych (runaway / advisor). Bez nowej głębokości promptu. |
| Settings | Nowe fieldsety `cursorCost.*` (karty ghost/pill jak Critical alert / Monthly budget). |
| Charts | Bez wymaganego zmian. 1.6 może później reuse’ować mix okresów; nie w MVP 1.6. |

## 4. Kolejność wdrożenia

Wdrażać **jeden MINOR naraz**. Nie wrzucać kodu 1.3–1.6 do PR 1.2.

1. **1.2 Runaway** — bez zależności od późniejszych funkcji. Opcjonalny sygnał burn-$ używa lokalnej stałej / settingu domyślnie **off**, nie capu z 1.3.
2. **1.3 Daily Guard** — niezależny od 1.2. Gdy oba istnieją, 1.2 może *opcjonalnie* traktować „wydatek w oknie ≥ pozostały dzienny cap” jako sygnał burn w follow-up PATCH — nie wymagane do wydania 1.3.
3. **1.4 Efficiency score** — Last N + próg spike; niezależny od 1.2/1.3.
4. **1.5 Model advisor** — rozszerza spend-by-model; niezależny, ale po 1.4, żeby układ kart Statistics był stabilny.
5. **1.6 Attribution** — niezależna ścieżka danych (mapa `globalState`). Na końcu, bo to fundament pod Team i rusza CSV / filtry.

v1.1 **Ignore** (`IgnoreStore`) zostaje leftover. Nie blokować 1.2 na Ignore.
